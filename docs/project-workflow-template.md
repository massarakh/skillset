# Профиль проекта — [название]

Сохрани профиль в репозитории проекта и добавь ссылку из его `AGENTS.md` или действующей инструкции. Используй принятые командой файлы, сервисы и команды.

| Поле | Что указать |
| --- | --- |
| **Владелец и ревизия skillset** | Кто поддерживает профиль, какая Git-ревизия набора используется, какие harness и роли поддерживаются. |
| **Контекст** | Ссылки на обзор системы, глоссарий, правила, действующие спецификации, NFR и ADR. |
| **Задачи** | Где найти Issue и её точную версию, как определяются готовность и блокировки. Для локального прогона укажи путь к Markdown. |
| **Среда и проверки** | Команды установки, сборки, тестов и линтеров. Условия обязательности CI и сканеров, доступный тестовый контур и данные. |
| **Доступ по ролям** | Какие инструменты и действия нужны разработчику, проверяющему и принимающему. Укажи утверждённый способ получения доступа. |
| **Доставка и приёмка** | Базовая ветка, правила PR/MR, обязательные проверяющие, кто подтверждает приёмку. |
| **Доказательства** | Где сохраняются diff, результаты команд, отчёты Spec и Standards и решение о приёмке. |

## Проверка подключения

1. Вызови `@setup-workspace` в OpenCode или `$setup-workspace` в Codex и укажи свою роль.
2. Проверь доступность проектных инструкций, источника Issue и нужных навыков.
3. Проверь, можно ли запустить штатные команды и выделить два независимых контекста для ревью. Сверь, где сохранится результат.
4. Запиши обнаруженные пробелы в доступах или оснастке и назначь ответственного за устранение каждого пробела.

Имена систем, команды и пути бери из этого проекта. Для учётных данных используй принятый командой менеджер секретов.
