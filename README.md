# Skillset

Версионируемый набор из 28 навыков для разработки с ИИ в существующих проектах. Основной цикл охватывает подключение специалиста, уточнение требований, подготовку Vision, декомпозицию, реализацию, независимое ревью и проверку результата.

- [Каталог навыков](docs/skills.md)
- [Шаблон профиля проекта](docs/project-workflow-template.md)
- [Происхождение и лицензии](docs/provenance.md)

## Установка в OpenCode и Codex

Нужны Git, Python 3.12+ и Make.

```sh
git clone https://github.com/massarakh/skillset.git
cd skillset
make setup
make check
make install
```

Менеджер устанавливает навыки в `~/.agents/skills`. При необходимости укажи отдельный каталог через `TARGET`. Для проекта выбери одну рабочую копию каждого навыка, чтобы предсказуемо разрешать совпадающие имена.

Открой OpenCode из корня проекта и выбирай навыки через `@имя`. Например:

```text
@how-would-you-do-it Разбери задачу <ID или ссылка> и предложи план.
```

В Codex используй явный вызов `$имя`, например `$implement <ID задачи>`. Реализация начинается после согласования плана и явного запуска `implement`.

## Подключение существующего проекта

1. Открой проект и вызови `@setup-workspace` в OpenCode или `$setup-workspace` в Codex. Укажи свою роль. Навык проверит профиль, доступные инструменты и ближайший рабочий шаг.
2. Если профиль нужно дополнить, согласуй правки с владельцем проекта. Используй [шаблон](docs/project-workflow-template.md) и ссылку из `AGENTS.md` или действующей инструкции.
3. Выбери одну небольшую задачу. Если требования уже согласованы, начни с технического плана. Для новой потребности начни с `grill-me` и `to-spec`.
4. После проверки плана запусти `implement`. Сопоставь результат с критериями, проведи `two-axis-review` в двух независимых контекстах и проверь изменение в рабочей среде по правилам проекта.

Для одного самостоятельного изменения достаточно Issue. Для крупной Vision используй `epic-to-issues`. `what-next` поддерживает локальный Markdown-бэклог. Доступ к внешнему трекеру, команды сборки и сканеры определяет профиль каждого проекта.

## Обновление и проверка набора

```sh
git pull --ff-only
make check
make diff
make install
```

| Команда | Назначение |
| --- | --- |
| `make list` | Показать навыки из каталога. |
| `make check test` | Проверить каталог и прогнать тесты менеджера. |
| `make diff` | Сравнить исходники и установленные копии. |
| `make install SKILL=to-spec` | Установить один навык и его зависимости. |
| `make rollback` | Откатить последнюю установку через менеджер. |
| `make upstream-check` | Проверить обновления у зарегистрированных источников. |
| `make upstream-diff SKILL=to-spec` | Сравнить источник с зафиксированной ревизией. |

Менеджер обнаруживает локально отредактированные копии и останавливается при конфликте. Источник правил навыка — его папка в `skills/`. Установка, откат и диагностика выполняются через менеджер.
